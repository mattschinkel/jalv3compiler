# Design: Finish the placement facade (A3 cleanup)

Generated by /office-hours on 2026-11-13
Branch: master
Repo: mattschinkel/jalv3compiler
Status: APPROVED
Mode: Builder

## Problem Statement

A3 ("one placement policy") landed 2026-11-13: every memory class routes
through one entry, `pic_mem_place()` (`src/libpic12/pic_var.c:4659`), with a
request/result split in `pic_mem.h`, gated byte-identical (L2 HEX manifest
2940 identical / 0 drift). A review of the landed code found the architecture
correct but the facade unfinished in four ways:

1. **Dead policies.** `PIC_MEM_PLACE_DEFER` and `PIC_MEM_PLACE_PINNED` are
   declared (`pic_mem.h:62-63`) with `case` branches (`pic_var.c:4671`,
   `4667`) but no call site passes either. Deferral happens inline in the
   SINGLE case (`pic_var.c:4700-4716`), duplicating the DEFER branch's logic.
   PINNED never enters the entry (`at` pins reserve directly).
2. **Hand-rolled FRAME requests.** All three FRAME call sites `memset` +
   field-fill by hand (`pic_var.c:3482`, `3574`, `3614`) instead of using an
   adapter, and the `report = needs_one` decision is duplicated in the caller.
3. **Three stride spellings.** The element-size-for-chunk-alignment rule is
   computed three ways: `pic_mem_request_group` (`pic_var.c:4610-4626`, whole
   multiple + non-bit), `pic_mem_object_get` (`pic_var.c:368-384`, same), and
   `pic_var_elem_sz_get` (`pic_var.c:4088-4099`, returns `esz ? esz : 1` with
   neither check). The third feeds the member-prefix pass (`pic_var.c:4140`).
4. **`req->region` is dead for GROUP.** The group adapter sets it
   (`pic_var.c:4601`) but `pic_group_place` hard-codes
   `PIC_MEM_REGION_DATA` (`pic_var.c:4246`) and the shared fallback
   hard-codes `PIC_MEM_REGION_SHARED` (`pic_var.c:3975`).

None of these changes output today; the corpus is green. Seam 3 is the one
with teeth: it is a latent footgun that the byte-identity gate cannot see
(no corpus program reaches the divergent case).

## What Makes This Cool

"One descriptor" is the allocator's core promise: the question "how big, how
aligned, how chunked" gets exactly one answer, computed once and carried
everywhere. These four seams are the last places that question is answered
twice. Closing them makes the A3 claim literally true instead of approximately
true, and removes the one silent-divergence trap left in the subsystem.

## Constraints

- Strict C89 (`-ansi -pedantic -Werror -Wall -Wshadow`); declarations at block
  top; no `//` comments in C files.
- Byte-identity is the standing gate: every step lands with L2 HEX manifest
  0 drift unless it is an intentional policy change with a witness + pin.
- No allocator rewrite. The investigation
  (`docs/investigations/unified_allocator_20261108.md`) explicitly rejected a
  fourth representation; this is finish-the-facade.
- The request/result split stays. `pic_mem_object_t` remains a borrowed view.

## Premises

1. The single-entry architecture is correct; better architecture means
   finishing it, not replacing it.
2. The stride/element-size rule has one home, computed once and carried in
   both the request and the object view.
3. Dead policy branches are a reader trap and should not live in the public
   header.

## Approaches Considered

### Approach A: Finish the facade (chosen)
Four small, independently byte-identity-gated edits (details in Next Steps).

### Approach B: Leave as-is
Freeze A3. Correct today, but the stride triple stays a latent footgun and
the header keeps promising policies that do not exist.

### Approach C: Full first-class allocator (A4/A5/A6/A7)
The investigation's endgame: one access plan, always-on audit, capacity
report. A separate, larger arc already in progress on the access-model track
(`doc/designs/one-access-model.md`). Does not fix the A3 seams.

## Recommended Approach

**A.** Closes every seam the review found, each step lands byte-identical,
and none of it redesigns a working subsystem. Effort: human ~half day,
CC ~30-60 min. It is the finish-the-facade pass the investigation's "DONE"
definition was always pointing at.

## Open Questions

- **Stride unification is the one step that may not be a pure refactor.**
  `pic_var_elem_sz_get` returns the element size without the non-bit /
  whole-multiple checks the other two apply. Before merging, verify whether
  the divergent case (a bit array, or a def whose byte size does not divide
  the member size) is reachable at the member-prefix call site
  (`pic_var.c:4140`). If unreachable, the merge is byte-identical by
  construction. If reachable, the strict rule (match
  `pic_mem_request_group`/`pic_mem_object_get`) is the intended one, and that
  step becomes a deliberate policy change needing a witness, not a silent
  merge.

## Success Criteria

- L2 HEX manifest 0 drift after each of the four steps (byte-identity proof).
- `pic_mem.h` declares only the three callable policies (SINGLE, FRAME,
  GROUP) plus the status (`PIC_MEM_DEFERRED`); no dead enum values.
- One stride function serves the group adapter, the object view, and the
  member-prefix pass; the grep check "the group placement reads only the
  request" still holds.
- Existing pins pass unchanged: `frame_overflow` 8/8 and the four runtime
  witnesses (`16f18857_picsim_isr_locals`,
  `16f18857_picsim_indirect_frame`, `16f18857_picsim_isr_chunked_local`,
  `16f887_gpsim_isr_chunk_walk`).

## Distribution Plan

No new distribution: lands as a compiler-source commit. Per the workspace
rule, a build that updates `bin/beta/jalv3-x86-64` commits that binary with
the change.

## Next Steps

1. **Delete the dead policies** (smallest, safest first). Remove
   `PIC_MEM_PLACE_DEFER` and `PIC_MEM_PLACE_PINNED` from `pic_mem.h` and
   their `case` branches from `pic_mem_place`; factor the inline defer
   (`pic_var.c:4700-4716`) into one `static` helper used by the SINGLE case.
   Gate: byte-identical.
2. **Add `pic_mem_request_frame(pf, proc, need, report, base, &req)`** and
   route the three hand-rolled FRAME call sites through it. Gate:
   byte-identical.
3. **Unify the stride rule.** One function computes "element size, 1 when
   bit/not-a-whole-multiple", used by `pic_mem_request_group`,
   `pic_mem_object_get`, and `pic_var_group_member_chunk_maps` (replacing
   `pic_var_elem_sz_get`). Resolve the Open Question first; if the divergent
   case is reachable, this step is a deliberate policy change with a witness.
4. **Make `req->region` honest for GROUP.** Either honor it in
   `pic_group_place`/`pic_variable_group_place_shared` or stop setting it in
   `pic_mem_request_group` (drop the field from the group's path with a
   comment saying the group search order is intrinsic). Gate: byte-identical.
5. **Write the fix doc** under `jalv3/fixes/` per the Documentation protocol,
   and update the A3 item in `TODOS.md` from "done; no open work" to "done;
   facade finished."

## The Assignment

Land step 1 (delete the dead DEFER/PINNED policies and factor the inline
defer into a helper) as a single byte-identical commit with its fix doc and
pin, exactly like the A3 increments that came before it. It is the smallest
complete unit that makes the "one entry" claim true, and it de-risks the
other three.

## Reviewer Concerns

Disposition: COMPLETED

Stop: PASS

No blocking findings remain. The 5 open minor finding(s) below are recorded for the user, not fixed.

### R1-1 — clarity (minor)

**Problem**

> Step 4 offers 'honor req->region in pic_group_place/pic_variable_group_place_shared' as an option, but the GROUP search is intrinsically multi-region: it tries the data window (pic_var.c:4246 hard-codes PIC_MEM_REGION_DATA), then the shared fallback (pic_var.c:3975 hard-codes PIC_MEM_REGION_SHARED), then segmented, while the adapter sets req->region = PIC_MEM_REGION_DATA (pic_var.c:4601). Honoring that single DATA value inside pic_variable_group_place_shared would replace its hard-coded SHARED search, which changes the group's window->shared->segmented order and cannot be byte-identical, so that branch is not buildable as written.

**Remedy**

> Drop the 'honor it' option and commit to the second: stop setting req->region in pic_mem_request_group and add the comment that the group search order (window -> shared -> segmented) is intrinsic.

### R1-2 — consistency (minor)

**Problem**

> The Success Criteria state 'L2 HEX manifest 0 drift after each of the four steps', but the Open Question explicitly allows step 3 to become 'a deliberate policy change needing a witness' when the divergent case is reachable, and a deliberate policy change is by definition not 0 drift. The Constraints section already carries the correct qualifier ('unless it is an intentional policy change with a witness + pin'), but the Success Criteria omit it, so the two sections read as contradictory.

**Remedy**

> Carry the Constraint's exception into the Success Criteria bullet, e.g. 'L2 HEX manifest 0 drift after each step unless it is the step-3 intentional policy change, which lands with its witness + pin.'

### R1-3 — clarity (minor)

**Problem**

> The Open Question asks to 'verify whether the divergent case ... is reachable at the member-prefix call site (pic_var.c:4140)', but the bit-array sub-case is reachable by construction: the guard at pic_var.c:4132 is 'variable_is_array(memb) || pic_variable_is_bit_array(memb)'. The operative question is whether the value diverges, not whether the case is reachable (variable_def_byte_sz_get at vardef.c:130-138 returns ceil(bits/8) for a bit def, which exceeds 1 only for bit elements wider than 8 bits).

**Remedy**

> Rephrase the Open Question around value divergence: does either rule return a different element size for any member that reaches line 4140 (a bit element wider than 8 bits, or a non-bit array whose element byte size does not divide the member size), rather than asking whether the case is reachable.

### R1-4 — clarity (minor)

**Problem**

> 'What Makes This Cool' says all four seams are 'the last places that question is answered twice', but only seam 2 (hand-rolled FRAME requests) and seam 3 (the stride triple) are double computations. Seam 1 (dead DEFER/PINNED enum values) and seam 4 (req->region set then ignored) are dead code/field issues, not a question answered twice, so the framing overstates what the seams are.

**Remedy**

> Reword the cool statement to fit the actual seams, e.g. 'the last places the one-descriptor promise is only approximately true', rather than the answered-twice framing that fits only two of the four.

### R1-5 — clarity (minor)

**Problem**

> Step 1 deletes PIC_MEM_PLACE_PINNED, reversing the landed docs' explicit decision to retain it: fixes/fix_pic_mem_place.md (Follow-ups) and fixes/fix_pic_mem_descriptor.md (Residual) both state the at-pin pass 'still reserves bytes directly -- that is the PINNED policy (no search)'. The design cites both docs as dependencies but does not acknowledge the reversal or say what documents the at-pin path afterward.

**Remedy**

> Add one sentence acknowledging that this reverses the landed docs' PINNED-retention decision and that the at-pin pass keeps its own comment documenting 'already reserved and pinned', so the meaning survives the enum deletion.
